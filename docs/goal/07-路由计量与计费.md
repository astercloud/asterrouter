# 路由、计量与计费

## 1. 设计目标

路由首先保证权限、能力和可靠性，再在硬约束内优化延迟与成本。计量记录技术事实，定价把技术事实解释为客户应收和供应商成本，账本保存不可变财务结果。三层不能混成一个倍率字段。

## 2. 路由输入

| 输入 | 示例 | 来源 |
| --- | --- | --- |
| 身份 | Profile、Tenant、Principal、Credential | Canonical Auth Context |
| 能力 | 文本/图片/视频/音频、流式、工具、取消 | 标准请求与 Gateway Model |
| 策略 | 模型白名单、Lane、Artifact、地域、预算 | API Key + Governance Policy |
| 供应 | Account 模型、健康、有效期、余额、冷却 | Provider Account Runtime |
| 容量 | RPM、TPM、并发、加权工作量 | Capacity Service |
| 质量 | 成功率、延迟、错误和信任证据 | 本地观测 + 有效 Feed |
| 经济 | 价格规则、有效采购价、预算 | Core Pricing + MonitorPrice |

Feed 和历史观测只能影响软排序，不能越过模型能力、租户政策、数据区域、信任下限或预算硬限制。

## 3. 候选筛选与排序

```text
1. Resolve Gateway Model
2. Filter enabled Model Routes
3. Filter Provider/Account status and expiration
4. Filter operation/modality/capability compatibility
5. Filter tenant/profile/policy/region constraints
6. Filter circuit/cooldown/risk blocks
7. Acquire rate/concurrency/weighted capacity eligibility
8. Group by priority tier
9. Score healthy candidates inside best eligible tier
10. Weighted selection with deterministic reason codes
```

建议评分只用于同一优先级和硬约束集合内：

```text
score = reliability_weight * reliability
      + latency_weight * normalized_latency
      + cost_weight * normalized_effective_cost
      + capacity_weight * remaining_capacity
      + trust_weight * trust_score
      - change_penalty * affinity_break
```

评分的输入版本、归一方法和权重进入决策快照。缺失数据使用保守默认值，不将“未知”解释为“最好”。

## 4. 容量模型

| 维度 | 文本 | 图片 | 视频 | 实时语音 |
| --- | --- | --- | --- | --- |
| 请求速率 | RPM | RPM | 创建/查询 RPM | Session 建立 RPM |
| Token | TPM | 可选文本 Token | Prompt Token 可选 | 音频/文本 Token |
| 并发 | 在途请求 | 在途生成数 | 加权在途任务 | 活跃 Session |
| 工作量 | 预估 Token | 张数×分辨率 | 时长×分辨率×模型权重 | Session 时长/通道 |

Provider Permit 获取必须原子化。Direct 和 Durable 共享同一容量池，并为交互请求保留可配置但有上限的份额，防止队列或实时流量相互饿死。

## 5. 重试、亲和与熔断

- 只对明确可重试错误、未提交响应和剩余时间/成本预算内的候选重试。
- 认证失败、余额不足、模型不存在等账号级错误触发对应冷却，不污染整个 Provider。
- 熔断器使用 Closed -> Open -> Half-open 状态；半开探测有并发上限。
- 会话、异步 Provider Task 和需要上下文缓存的调用保持账号亲和。
- Route 失败链记录每个候选的排除或失败 reason code，但对客户端隐藏敏感拓扑。

## 6. 标准 Usage

`UsageRecord` 至少支持：

- 文本：input/output/cached/reasoning tokens。
- 图片：数量、尺寸、质量、输入/输出图像单位。
- 视频：生成秒数、分辨率、帧率或 Provider 计费单位。
- 音频：输入/输出秒数、字符、音频 Token。
- 实时：Session 秒数、音频/文本事件与 Provider 单位。
- 通用：Operation、Attempt、Model、Provider Account、Tenant、Credential、时间和状态。

Usage 的来源带置信等级：Provider 最终 Usage > Provider 账单可关联明细 > Core 确定性计算 > 估算。估算必须显式标记，不能静默作为供应商应付最终事实。

## 7. 价格模型

### 7.1 两条价格链

| 链路 | 回答问题 | 规则来源 |
| --- | --- | --- |
| Customer Price | 向使用方收多少 | Profile 套餐、合同、Pricing Rule |
| Provider Cost | 上游实际花多少 | Provider 报价、账号折扣、账单、Effective Price |

二者分别版本化和评估：

```text
UsageRecord + Customer Pricing Context -> Customer Evaluation -> Receivable Ledger
UsageRecord + Provider Cost Context     -> Cost Evaluation     -> Payable/Cost Ledger
```

毛利是两个不可变结果的派生指标，不反向修改任一分录。

### 7.2 价格表达式

- 输入只能是受支持的 Usage 维度、模型、时间、Tenant/Profile 和已发布上下文。
- 表达式必须有类型、边界、舍入和货币规则，不执行任意脚本。
- 发布前用固定 Case、历史影子数据和极值进行模拟。
- 已发布版本不可修改；调价创建新 revision 与生效窗口。
- 一次 Operation 固化适用版本，长任务不中途换价。

## 8. Billing Hold 与结算

1. Admission 根据最大允许输出、任务规格和价格版本计算保守预估。
2. 对有余额/预算约束的主体创建 Hold；失败则不调用 Provider。
3. Provider 完成后以标准 Usage 进行最终评估。
4. 原子写入 Usage、Evaluation、Ledger、Hold 释放/结算和 Outbox。
5. 实际费用低于预扣则释放差额；高于预扣按产品策略补扣或进入异常，不允许无界透支。
6. 取消、失败和部分成功按已发生的可验证 Usage 结算。

## 9. 幂等与纠错

- `Operation + Attempt + Usage Version + Purpose` 唯一确定账务分录。
- 重放 Usage Event 返回既有结果，不重复扣费。
- Provider 后补 Usage 以新版本追加并产生差额分录。
- 错误分录通过 Reversal 和 Replacement 修正，不 UPDATE/DELETE 历史金额。
- 手工调整必须关联原因、操作者、审批者和原始对象。

## 10. 成本感知调度

成本优化生效的前提：

1. 候选满足能力、信任、可靠性、延迟和合同硬下限。
2. 有效价格的来源、时间窗、货币和置信度符合策略。
3. 优化决定记录预期基线、选中候选、价差和 reason code。
4. 完成后用实际 Usage 和成本生成 Savings Evidence。

不能仅因报价低就把流量导向未知质量账号；不能用过期 Feed 覆盖本地明确的熔断或风险阻止。

## 11. 对账

| 对账层 | 左侧 | 右侧 | 主要差异 |
| --- | --- | --- | --- |
| 请求对账 | AIOperation/Attempt | UsageRecord | 漏 Usage、重复、版本不一致 |
| 客户对账 | Usage + Customer Evaluation | Customer Ledger/Statement | 价格版本、舍入、调整 |
| 供应商对账 | Usage + Cost Evaluation | Provider Bill | Provider 延迟、聚合单位、税费 |
| 资金对账 | Ledger | Wallet/Payment/Grant | 充值、退款、并发余额 |

对账差异形成独立 Case，不修改原始调用事实。所有报表可回溯到 Operation 和价格快照。

## 12. 路由与计费验收

- 固定输入、状态和策略能重放出相同候选集合与 reason code。
- 并发压测不突破 Account RPM/TPM/并发硬上限。
- 流式中断、Provider 超时、Callback 重放不产生重复 Ledger。
- 已发布价格在历史数据重算中结果稳定，金额无浮点漂移。
- Customer Price 与 Provider Cost 任一缺失时明确显示未完成，不伪造毛利。
- 成本优化实验同时验证成功率、P95、重试放大、成本和节省证据。
