# 用户故事与用例

## 1. 编写标准

用户故事使用“作为 / 我需要 / 从而”描述价值；详细用例包含前置条件、主流程、异常流和验收。用例 ID 与 PRD、自动化测试和发布证据建立追踪。

## 3. UC-INS-001 首次安装

**前置条件**：持久存储和稳定 Secret 可用，实例未初始化。

**主流程**：

1. 所有者打开 Setup，系统显示四个 Profile 的职责与不可逆影响。
2. 选择一个 Profile，创建管理员并验证生产安全要求。
3. 服务在事务内创建 Profile、基础权限和默认设置。
4. 初始化成功后关闭 Setup，用户进入对应 Surface。
5. 添加 Provider/Account/Model/Route，创建 Key 并完成测试调用。

**异常流**：并发提交只允许一个成功；中途失败可重试；已有初始化返回明确状态而非覆盖。

**验收**：无半初始化数据；生产环境拒绝 Memory Repository、空密码和不稳定 Secret。

## 4. UC-IAM-001 创建 Service Key

**前置条件**：Tenant/Service Principal Active，操作者拥有 Key Create 权限。

**主流程**：

1. 选择 Service Principal 和 Governance Policy。
2. 设置 Scope、模型、操作、限额、CIDR、过期和 Artifact Policy。
3. 服务计算最终约束，拒绝超过操作者委托上限的配置。
4. 生成 Key，保存 Hash/Fingerprint，明文展示一次。
5. 审计记录创建者、Principal、Policy 和限制摘要。

**异常流**：Principal Disabled、最后预算不足或 Policy 冲突时拒绝，不生成 Key。

**验收**：后续任何 API 都无法取回明文；越权 Scope 的调用被拒绝且有 reason code。

## 5. UC-IAM-002 轮换与撤销

1. Owner 请求轮换并选择短重叠窗口。
2. 系统签发新 Key，旧 Key 进入 Retiring。
3. Owner 根据 Last Used 确认业务已迁移。
4. 到期后旧 Key 自动 Retired；紧急场景可立即 Disabled。

验收：并发轮换不会产生多个无关系 Family；缓存节点在撤销目标时间内拒绝旧 Key。

## 6. UC-GW-001 Direct 流式调用

**前置条件**：Key、Model Route、Provider Account 和预算有效。

1. 客户发送带 `stream=true` 的请求。
2. Core 完成身份、策略、Admission、Hold、Route 与 Permit。
3. Provider Adapter 建立上游流并标准化事件。
4. 首个事件前的可重试失败可选择下一候选。
5. 首个事件后发生失败则终止流、记录 Usage/Trace，不拼接另一路响应。
6. 结算 Hold 并异步投递 Usage Sink。

验收：断连、超时、Provider 5xx、空 Usage 和部分 Usage 均有确定账务语义。

## 7. UC-JOB-001 创建视频任务

**前置条件**：支持视频的 Gateway Model、Provider Adapter、Artifact Policy 和幂等键。

1. 客户上传首尾帧或引用已有 Artifact，提交规格。
2. API 校验权限、容量队列上限和预算，事务创建 Operation/Job/Hold。
3. Worker 获得 Lease，选择 Route，持久化 Dispatch Intent。
4. Adapter 创建 Provider Task；超时进入 Reconcile，不盲重发。
5. Poll/Callback 更新进度，最终摄取并校验视频 Artifact。
6. Core 记录 Usage、成本、Ledger，完成 Job。
7. 客户刷新或换设备后通过 Job ID 继续查询与下载。

异常流：排队取消不调用 Provider；执行中取消尽力通知 Provider；Artifact 摄取失败不把 Job 伪装成完整成功。

## 8. UC-ART-001 客户 Sink 交付

1. 管理员创建与 Tenant 绑定的 S3-compatible Sink，Secret 只提交不回显。
2. Key/Policy 选择 `customer_sink` 与目标 Sink。
3. Artifact Ready 后 Worker 写入隔离 Prefix，校验大小与摘要。
4. 写 Delivery 状态和客户引用；失败按退避重试。
5. 达到上限进入 `delivery_failed`，管理员可修复配置后重试。

验收：其他 Tenant 无法引用 Sink；对象写成功但确认超时时通过 Head/Checksum Reconcile，不重复生成内容。

## 9. UC-FIN-001 价格发布与结算

1. FinOps 创建 Draft 价格版本。
2. 系统对标准 Case、历史影子数据和极值执行模拟。
3. 独立审批者批准生效窗口。
4. 新 Operation 固化版本，旧 Operation 和在途 Job 不换价。
5. Usage 完成后分别生成 Customer/Cost Evaluation 和 Ledger。

验收：同一 Usage 重放不重复分录；错误规则通过新版本与冲正修复。

## 10. UC-PLG-001 安装 Sidecar 插件

**前置条件**：Catalog/离线包有效，操作者有插件管理权限。

1. 管理员查看版本、Vendor、Tier、Core/Profile/OS 兼容和权限差异。
2. 系统下载到 Staging，校验签名、Digest、文件路径和 Entitlement。
3. 创建安装记录并原子激活 Package。
4. 管理员配置非敏感设置和 Secret。
5. 启用时 Supervisor 启动 Sidecar，完成 Token 握手与健康检查。
6. Frontend Contribution 只在声明 Surface 出现。

异常流：签名失败不激活；Sidecar 失败保持可诊断状态；上一版本仍可回滚。

## 11. UC-PLG-002 插件审核发布

1. 开发者创建 Project 和版本，上传不可变 Package。
2. AsterCloud 校验摘要并运行 Manifest、依赖、Secret、恶意代码、权限和兼容扫描。
3. 审核员查看证据、权限用途、数据流和测试结果。
4. 批准后由受保护签名边界生成签名 Package/Catalog 记录。
5. 先进入 Preview Channel，满足观察窗口后进入 Stable。

验收：拒绝原因机器可读；同版本内容不可替换；签名操作有独立审计。

## 12. UC-CLD-001 离线授权与安装

1. 离线实例导出带 Instance 公钥/指纹、Nonce 和请求能力的文件。
2. 管理员在联网环境登录 AsterCloud 上传请求并完成授权。
3. AsterCloud 返回签名、可选加密的 License/Catalog/Package Bundle。
4. 离线实例验签、检查受众/Nonce/时间并导入本地快照。
5. 插件安装和运行不再访问公网。

验收：篡改、其他实例文件、过期、序号回退和撤销均拒绝；重复导入幂等。

## 13. UC-SRE-001 Provider 故障处置

1. 告警显示受影响 Model/Account、成功率、错误和重试放大。
2. SRE 从样本 request_id 查看候选、排除原因、Attempt 与 Provider 错误。
3. 使用 Simulator 预览降权/冷却影响。
4. 发布有过期时间的临时变更，监控成功率、延迟、成本和容量。
5. Provider 恢复后半开探测，逐步恢复 Route。

验收：动作可回滚、有审计；临时配置自动到期；恢复以业务 SLI 证明。

## 15. 自动化追踪要求

每个 P0 用例至少有：Service 单元测试、Repository 契约测试、HTTP/协议集成测试和一个发布环境黑盒场景。涉及浏览器的用例补充桌面/移动关键路径；涉及故障恢复的用例必须真实终止进程或中断依赖，不能只 Mock 返回错误。
