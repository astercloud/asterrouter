# 术语与口径

## 1. 使用规则

- 产品、代码、API 和 UI 优先使用本表术语。
- 首次出现英文专有名词可附中文解释，后续保持同一写法。
- `Provider`、`Account`、`Model`、`Route`、`Plugin` 不互相替代。
- “当前支持”只用于 `CURRENT`，未来能力使用“目标”或 `TARGET`。

## 2. 产品与系统

| 术语 | 定义 | 避免使用 |
| --- | --- | --- |
| AsterRouter | 可私有部署的 AI 访问与供应平台 | 仅称“代理”或“中转” |
| AsterCloud | AsterRouter 可选官方服务中心 | 云端控制面、远程管理中心 |
| Core | 拥有身份、路由、执行、计量、Artifact 和审计不变量的本地核心 | 内置插件集合 |
| Plugin Host | 管理插件安装、权限、贡献点和 Sidecar 的 Core 组件 | 插件市场 |
| Surface | 面向一类角色的 UI/API 产品面 | Tenant、Profile |
| Profile | 首次安装选择的部署角色能力包 | 用户角色、运行进程 Role |
| Role | 进程职责或权限角色，必须结合语境 | Profile |

## 3. 身份与租户

| 术语 | 定义 |
| --- | --- |
| User | 可登录管理面的人类主体投影 |
| Identity | User 的密码/OIDC 等登录凭据绑定 |
| Tenant | 业务数据与权限隔离边界 |
| Principal | 可被授权的稳定主体，可为人、服务、开发者或集成 |
| Gateway Principal | 专用于数据面调用归属的机器/业务主体 |
| Credential | 用于证明身份的秘密或签名材料，如 API Key |
| API Key | Gateway Credential；不是 User 或 Principal 本身 |
| ServiceAccount | 面向自动化工作负载的机器身份；目标态映射 Gateway Principal |
| External Auth Integration | 验证外部平台签名 Context/JWT 的信任配置 |
| Canonical Auth Context | 单次请求经验证、归一后的身份与权限上下文 |
| Scope | 权限作用域或 Credential 可执行动作集合 |
| RoleBinding | Principal 在特定资源 Scope 中获得角色的关系 |

## 4. 供应与模型

| 术语 | 定义 |
| --- | --- |
| Provider | AI 协议/服务供应入口，如 OpenAI-compatible、Bedrock、Vertex |
| Provider Connection | Provider 的 Base URL、协议类型和全局状态配置 |
| Provider Account | 一组上游凭据、容量、健康、模型和调度属性 |
| Provider Secret | Provider Account 的认证秘密 |
| Account Model | 某 Provider Account 实际暴露的上游模型 |
| Gateway Model | 客户可见、稳定、带能力契约的模型名 |
| Model Route | Gateway Model 到 Provider Account/Upstream Model 的候选映射 |
| Route Decision | 一次调用对候选筛选、排序和选择的可解释结果 |
| Capability | 模型或插件可提供的明确能力，不等同 Permission |
| Capacity Permit | 在速率、并发或加权工作量约束下获得的执行许可 |
| Affinity | 同一会话/任务优先维持 Provider Account 的约束 |
| Circuit Breaker | 按错误信号暂时停止选择故障资源的状态机 |

## 5. 执行与协议

| 术语 | 定义 |
| --- | --- |
| Protocol Edge | 解析 OpenAI-compatible 等外部协议的边界层 |
| Direct Lane | 在一次连接内直接返回 JSON/SSE 的执行通道 |
| Durable Lane | 先持久化 Job，再异步执行和查询结果的通道 |
| Realtime Session | 具有连接生命周期和双向事件的实时会话 |
| AIOperation | 一次业务 AI 操作的顶层权威事实 |
| AIAttempt | Operation 对某一 Provider Route 的一次具体尝试 |
| AIJob | Durable Lane 的本地可恢复任务 |
| Provider Task | Provider 侧异步任务，归属某个 Attempt |
| Dispatch | 将一个 Attempt 提交给 Provider 的动作 |
| Reconcile | 查询外部事实并与本地状态收敛的动作 |
| Commit Point | 之后不可再安全换源或重放的提交边界 |
| Idempotency Key | 调用方用于去重同一意图的稳定键 |

## 6. 计量与财务

| 术语 | 定义 |
| --- | --- |
| Usage | Token、秒数、图像单位等标准技术用量 |
| UsageRecord | 一次 Operation/Attempt 的版本化用量事实 |
| PricingRuleVersion | 已版本化、可发布的定价规则 |
| PricingEvaluation | Usage 在某规则版本下的计算结果 |
| Billing Hold | 执行前对余额/预算的预留 |
| Ledger | 只追加的财务分录集合 |
| Customer Price | 面向使用方的应收价格 |
| Provider Cost | 上游资源的采购/实际成本 |
| Effective Price | 在某来源与时间窗内观测的有效采购价格 |
| Savings Evidence | 成本决策相对基线的可回溯节省证明 |
| Reversal | 对错误账务分录进行冲正的新分录 |

## 7. Artifact

| 术语 | 定义 |
| --- | --- |
| Artifact | AI 操作的输入、预览、最终或派生产物元数据 |
| Artifact Store | Local/S3-compatible 等内容存储驱动 |
| Artifact Policy | `proxy_only`、`temporary`、`managed`、`customer_sink`、`metadata_only` |
| Artifact Sink | 客户指定的产物交付目标 |
| Retention | 产物保留、到期、法律保留与删除策略 |
| Delivery | 将产物写入目标 Sink 并形成可验证结果的过程 |

## 8. 插件与官方服务

| 术语 | 定义 |
| --- | --- |
| Plugin Manifest | 插件 ID、版本、Runtime、Surface、Capability、Permission 等声明 |
| Plugin Package | 带 Manifest、平台资产、Digest 和签名的不可变分发包 |
| Installation | 某实例选择和激活的插件版本事实 |
| Contribution | 插件向前端、Adapter、通知等扩展点提供的能力 |
| Sidecar | 由 Plugin Host 管理的本地独立插件进程 |
| Host API | 插件以最小权限访问 Core 能力的版本化 API |
| Catalog Snapshot | AsterCloud 发布、AsterRouter 验签保存的目录快照 |
| License | 客户/实例获得产品使用权的签名授权 |
| Entitlement | License 下的细粒度功能、额度或服务权利 |
| Official Feed | 官方服务发布的签名、可选加密数据包 |
| Security Advisory | 说明漏洞、影响版本、严重度和处置的签名公告 |

## 9. 运行与可靠性

| 术语 | 定义 |
| --- | --- |
| Fact Source | 对某业务事实拥有最终裁决权的存储 |
| Projection | 从外部或权威事实生成的本地可重建视图 |
| Outbox | 与业务事务原子写入、随后异步发布的事件记录 |
| Lease | 有过期时间的临时独占处理权 |
| CAS | 基于版本或预期状态的条件更新 |
| Ready Index | 可从 Job 事实重建的待执行索引 |
| SLI/SLO | 服务水平指标/目标 |
| RPO/RTO | 可容忍数据损失点/恢复时间目标 |
| Grace Period | 在线授权不可用时允许使用最后有效授权的有限窗口 |
| Fail Closed | 不确定时拒绝扩大权限或执行危险动作 |

## 10. 状态口径

| 状态 | 定义 |
| --- | --- |
| `CURRENT` | 当前代码和测试可验证 |
| `TARGET` | 已决定但可能尚未实现的目标 |
| `COMPAT` | 有现有调用方的兼容路径 |
| `DEPRECATED` | 已有替代方案、停止新增依赖 |
| `DEAD` | 应删除的无合法路径 |

“支持”必须附带成熟度：Experimental、Preview 或 GA。不得用“已完成”描述只有 UI、表或 Happy Path 的能力。

## 11. 命名规范

- API 使用 `snake_case` JSON 字段，ID 带领域前缀。
- Go 类型使用业务全称，避免无语义的 `Data`、`Info`、`Manager`。
- 数据库表使用复数 `snake_case`，外键显式以 `_id` 结尾。
- Event 使用 `domain.entity.action.vN` 或项目统一等价格式。
- 时间统一 UTC 存储、RFC 3339 传输；金额使用整数 micros 和 ISO 货币代码。
- Provider 对外稳定名与上游模型名分开，不把供应商版本泄露为永久客户契约。
