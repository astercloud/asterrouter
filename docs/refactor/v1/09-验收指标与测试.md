# 验收指标与测试

## 1. 验收原则

V1 的成功不是页面更少或视觉更新，而是用户更快完成真实调用，日常更少巡检，异常时更容易做出正确动作，同时 Core 零回归。

验收分四层：

1. 用户结果；
2. 体验与文档质量；
3. 工程正确性；
4. 生态、AI 辅助与离线边界。

任何一层出现阻断问题都不能用其他层的高分抵消。

## 2. 北极星指标

### 2.1 Time to First Governed Call

定义：从用户首次进入未完成 Setup/Onboarding，到真实请求通过 AsterRouter 并完成以下事实的时间：

- 有效 Application/Principal 与 Credential；
- Policy/Scope Admission 成功；
- 选择有效 Route 并完成 Provider Attempt；
- 返回成功结果；
- 写入 Usage 和 Trace/Audit 关联。

不把前端“测试成功”事件单独视为完成。

目标：

- 标准网络、已有可用 Provider 凭据的场景，P50 小于 10 分钟；
- 同一标准场景 P90 小于 20 分钟；
- 外部 Provider 凭据申请、人工网络审批时间从计时中单独标记，不静默剔除；
- 中断恢复后的总主动操作时间和自然时间分别报告。

十分钟是首轮设计假设。若不同部署类型存在稳定且合理的时间差，应按场景建立基线，而不是通过隐藏步骤或停止计时维持数字。

### 2.2 事件口径

| 事件 | 必要属性 |
| --- | --- |
| `onboarding_started` | instance intent、new/existing、profile mapping |
| `model_source_verified` | source type、duration、result class |
| `model_published` | capability、recommended/manual |
| `application_created` | application type、default changed count |
| `credential_issued` | type、expiry class，不含明文或 hash |
| `first_governed_call_succeeded` | duration、model、test/real、policy/usage/trace complete |
| `onboarding_abandoned` | step、error class、created object count |

分析事件不得包含 Provider Secret、Key、请求/响应内容、完整 Endpoint Query 和个人敏感数据。

## 3. 核心产品指标

| 指标 | V1 目标 | 说明 |
| --- | --- | --- |
| 首次闭环完成率 | 测试样本不低于 85% | 从开始到首次真实成功调用 |
| 标准首日路径无文档完成率 | 不低于 80% | 诊断界面是否自解释，不评价文档价值 |
| 专业文档任务完成率 | 不低于 90% | 部署、权限、故障和 API 任务使用文档完成 |
| 文档事实准确率 | 100% | 命令、字段、默认值和边界与当前版本一致 |
| 默认路径业务步骤 | 不超过 4 步 | 来源、模型、应用、验证 |
| 默认路径人工决策 | 不超过 8 个 | 文本输入和明确选择，不计复制动作 |
| L1 日常任务完成率 | 不低于 90% | 不进入诊断层完成常见任务 |
| Provider 变更应用零改动率 | 100%（兼容模型名时） | 上游切换不改业务 Endpoint/Key |
| 旧书签有效迁移率 | 100% | 到达正确目标或明确整理页 |

首轮目标用于发布门槛，生产基线建立后可收紧，但不能为了达标修改事件口径。

五项导航、两种使用意图、十分钟目标和 L1/L2/L3 分层都属于设计假设。指标用于验证它们，而不是用于证明已经决定的方案正确。

## 4. Attention Item 指标

| 指标 | 目标/约束 |
| --- | --- |
| 有效处理率 | 用户执行建议动作后确实恢复或降低风险的比例持续上升 |
| 无行动事项占比 | 低于 5% |
| 重复事项率 | 同根因同影响窗口低于 2% |
| 自动恢复关闭延迟 | 来源恢复后在投影 SLA 内关闭 |
| 错误严重度率 | 不得把实际中断标为正常；高风险漏报为阻断问题 |
| 忽略后复发可解释性 | 100% 保留忽略人、原因、期限和新影响 |

首页红点数量、告警总数和通知打开率不是成功指标。目标是减少用户不必要的反应，而不是提高点击。

## 5. 守护指标

以下指标必须不劣于重构前基线：

- Gateway 成功率、P95/P99 延迟和流式首字节；
- Admission、Policy 和 Tenant 隔离正确率；
- Usage 完整率、Pricing 可解释率和 Ledger 平衡；
- Job 状态一致性、重复 Dispatch 和 Artifact 越权率；
- Provider Secret、Key 和内容泄露事件为零；
- Plugin Sidecar 故障对 Core 的扩散为零；
- AsterCloud 断网时数据面可用性；
- 管理 API P95、首页投影延迟和前端资源大小预算。

V1 Product Facade 不进入 Gateway 热路径，因此其故障不应增加 Gateway 请求延迟。

## 6. 用户测试

### 6.1 样本

至少覆盖：

- 首次使用 AI Gateway 的开发者；
- 熟悉 OpenAI 兼容 API、但不了解 AsterRouter 的平台工程师；
- 企业管理员或 FinOps；
- 服务网关运营者；
- 只使用委托 Portal 的应用负责人；
- 插件/工具管理员。
- 安全、合规或事故响应人员。

产品开发成员不能替代外部样本。

### 6.2 任务

不提供步骤，只给结果目标：

1. 让示例应用通过 AsterRouter 调用指定模型；
2. 给现有模型增加备用来源；
3. 轮换正在使用的应用凭据；
4. 找出本月费用异常来自哪个应用；
5. 处理一个来源故障和一个 Usage Sink 积压；
6. 安装并启用图片工作台，说明它能访问什么；
7. 在 AsterCloud 断网后判断现有调用是否受影响。
8. 只依赖文档完成一次权限排查或灾难恢复演练。
9. 分别通过导航、搜索和 AI 辅助定位同一跨来源故障。

记录完成率、主动操作时间、错误路径、询问的问题和用户使用的词。测试主持人不解释产品术语。

### 6.3 通过标准

- 用户能用自己的话说出 AsterRouter 当前是否正常；
- 用户不需要区分 Provider Account、Route 和 Routing Group 完成供应任务；
- 用户理解 Application Credential 与 Provider Credential 不同；
- 用户能说明插件数据和 AsterCloud 的边界；
- 失败后知道数据是否已保存以及下一步。
- 专业用户能直接进入所需证据，不因界面简化增加排障步骤。
- AI 结论可以通过来源证据复核，关闭 AI 后任务仍能完成。

## 7. 自动化测试矩阵

### 7.1 后端

| 范围 | 必测内容 |
| --- | --- |
| Product Facade | 聚合口径、部分失败、新鲜度、分页、缓存隔离 |
| Onboarding | 幂等、恢复、并发、Secret 一次性、补偿状态 |
| Application | Principal/Key/Policy/Usage 映射、轮换状态 |
| PublishedModel | Model/Route/Account 健康、供应模拟、能力差异 |
| Attention | 聚合、严重度、自动恢复、忽略/延后、动作验证 |
| 权限 | Profile、Role、Tenant、Scope 的正向与负向矩阵 |
| 兼容 | 现有 Gateway、Management API 和旧数据 Fixture |
| 账务 | Usage 唯一性、Pricing 版本、Ledger 平衡、未知成本 |

### 7.2 前端

| 范围 | 必测内容 |
| --- | --- |
| 路由 | 新主导航、旧深链、权限和条件入口 |
| 状态 | loading、empty、partial、error、forbidden、stale |
| Onboarding | 刷新恢复、复制一次性 Key、真实验证、失败重试 |
| 应用 | 新建、轮换、权限、预算和活动下钻 |
| 模型 | 发布、增加来源、降级、供应高级详情 |
| 用量 | 时区、币种、未知价格、筛选与导出 |
| Attention | 动作、验证、忽略、聚合和来源证据 |
| 响应式 | 390x844、768x1024、1280x800、1440x900 |
| 可访问性 | 键盘、焦点、读屏名称、对比度、动态通知 |
| AI 辅助 | 权限继承、证据引用、未知表达、命令确认、关闭后的确定性退路 |

### 7.3 浏览器端到端场景

- 全新团队网关完成首次调用；
- 全新服务网关分别选择外部系统和内置客户；
- 现有四 Profile 升级后进入迁移摘要；
- 旧 Admin/Console/Operator/Platform 书签跳转；
- Key 丢失明文后只能轮换；
- 来源认证失败、模型发现失败、首次请求失败分别恢复；
- 主要来源中断后备用接管，首页文案准确；
- 无备用 Route 时显示受影响应用和修复动作；
- 移动端完成核心闭环，无重叠和横向溢出。

## 8. 真实基础设施测试

内存测试不能覆盖以下风险，发布前至少执行：

- PostgreSQL Migration、事务并发、分页和大数据量查询；
- Redis 不可达、缓存陈旧和恢复；
- 单 Origin 生产构建的登录、CSRF、Cookie 与静态资源；
- Docker/Linux 运行、进程关闭和 Plugin Sidecar 生命周期；
- 真实或受控 Provider 的流式、错误映射、限流和超时；
- Object Store Artifact、签名 Package 和离线目录导入；
- Usage Sink 失败、重试、积压和幂等送达。

## 9. AsterCloud 与插件测试

| 场景 | 预期 |
| --- | --- |
| AsterCloud 从未连接 | Core 完整可用，不出现阻塞推广 |
| AsterCloud 运行中断开 | Gateway 不受影响，显示最后同步时间 |
| Catalog/Feed 过期 | 显示陈旧度，按策略限制新动作 |
| License 宽限期 | 影响前提醒，现有能力按规则运行 |
| Package 被篡改 | 安装拒绝，无残留 Runtime/导航 |
| Permission 升级 | 必须重新批准差异 |
| Sidecar 崩溃循环 | 隔离、退避、Attention 准确，Core 正常 |
| 插件禁用/卸载 | 导航消失，历史活动可读，数据按选择保留 |
| 恶意版本撤销 | 本地匹配 Digest、审计并执行本地策略 |
| 跨 Tenant 调用 | Host 与 Core 双重拒绝，不泄露存在性 |

## 10. 安全验收

- Provider Secret、应用 Key 不出现在日志、错误、Trace、分析事件、URL 和诊断包；
- Credential 明文只在一次性响应和受控前端状态出现；
- 所有 Product Facade 查询执行 Tenant/Scope 负向测试；
- 路由解析器不能被旧 URL 用于跨 Tenant 枚举；
- Attention 推荐动作重新鉴权，不信任投影中的权限；
- 插件 Contribution 不能注入未批准脚本、导航、网络域和全局通知；
- CSRF、SSRF、Open Redirect、XSS、文件导入和 Package 路径穿越测试通过；
- 危险动作记录 Actor、原因、影响对象和结果。
- AI 草案不能绕过现有鉴权、幂等、确认和审计，模型上下文不得包含无权数据或明文 Secret。

## 11. 性能预算

预算以 Phase 0 基线校准，至少遵循：

- `/api/v1/home` 不做无界 Trace/Usage 扫描，P95 满足管理 API 预算；
- 应用和模型列表首屏只请求一个聚合接口，不产生浏览器 N+1；
- Attention 影响计算异步化时标明新鲜度；
- 新管理 UI 不增加 Gateway 热路径调用；
- 前端按页面和工具分包，未安装/未进入的工作台不加载；
- 大列表在真实规模 Fixture 下验证查询计划、游标和内存。

## 12. 发布判定

V1 可以默认开启必须同时满足：

- 北极星与核心产品指标达到阶段目标；
- 安全、Gateway、Usage、账务、Job、Artifact 零阻断回归；
- 四 Profile、主要角色和委托入口通过权限矩阵；
- AsterCloud 断网与官方插件故障演练通过；
- 旧路由迁移率 100%，回退演练通过；
- 桌面、移动、键盘和读屏核心流程通过；
- 所有已知差异有 Owner、影响、临时措施和关闭条件。
- 关键体验假设已经按角色验证，反证和例外场景有明确处置。

页面完成、单元测试通过或内部团队主观满意，任何一项都不能单独作为发布依据。

## 13. 设计假设复审

每个稳定发布周期复审以下内容：

| 假设 | 主要证据 | 可能动作 |
| --- | --- | --- |
| 五项导航足够 | 首次点击成功率、搜索依赖、旧路由回访 | 改名、重组或增加有证据的入口 |
| 两种意图可完成 Profile 映射 | Setup 犹豫、改配和支持工单 | 调整问题或增加明确场景 |
| “今天”能减少巡检 | 漏报、误报、Dashboard 回访 | 调整 Attention 或增加 SLO 摘要 |
| Application/PublishedModel 符合用户心智 | 归属整理率、跨页次数、错误修改 | 修正投影边界，不迁移 Core 事实 |
| 默认值降低决策成本 | 默认修改率、生产回退和安全事件 | 修改依据、适用条件或取消自动应用 |
| AI 辅助提高效率 | 可复核率、误导率、完成时间、放弃率 | 保持实验、缩小范围或移除 |

复审结果需要记录“保留、调整、停止”及证据。没有证据的偏好不能升级为长期产品不变量。
