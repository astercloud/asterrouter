# 关键界面与交互规格

## 1. 通用交互原则

每个页面必须先回答一个问题，再提供一个主要动作。页面不使用功能介绍、弹窗教程或成排统计卡片代替任务设计。

通用顺序：

```text
结论 -> 影响 -> 主动作 -> 必要证据 -> 高级详情
```

通用规则：

- 一个页面最多一个视觉主按钮；并列动作使用次要按钮或菜单。
- 保存前说明会改变什么，保存后说明结果是否生效。
- 长操作返回可离开的进度状态，不锁住页面等待。
- 删除、撤销、停用和覆盖配置必须说明影响范围并可审计。
- 技术错误保留 request ID，但先给用户可行动的解释。
- 自动建议标明依据、数据时间和预计影响，不能用自然语言掩盖未知。

## 2. “今天”首页

### 2.1 正常状态

首屏只显示运行结论和最少证据：

> 一切正常。3 个应用正在使用 5 个模型，今天没有需要你处理的事项。

下面显示：

- 最近 24 小时成功调用与失败变化；
- 当前使用中的应用和模型数量；
- 最近完成的配置、轮换或恢复动作；
- 监控覆盖与数据新鲜度摘要；
- “查看活动”次要入口。

不展示 Provider 数、Key 总数、插件总数等不能指导行动的指标。

“一切正常”只有在关键健康来源可用且位于新鲜度窗口内时出现。监控缺失、投影延迟或账务尚未汇总时，分别显示未知范围和最后更新时间。

### 2.2 有待处理事项

按紧急度和预计影响时间排序，不按告警产生时间简单排序：

```text
2 件事需要处理

[今天处理] 订单助手的访问凭据将在 7 天后到期
影响：凭据过期后，订单助手将无法调用 2 个模型
建议：现在创建新凭据，并在确认新凭据开始使用后撤销旧凭据
[开始轮换]
```

已经自动降级且业务无影响的事项使用“正在保护你”语气，不制造故障恐慌。

### 2.3 新实例与中断恢复

没有完成核心闭环时，首页只显示恢复卡片：当前完成到哪一步、已保存什么、下一步是什么。主按钮为“继续接入”。不同时展示空 Dashboard。

## 3. 首次接入向导

### 3.1 容器

- 顶部显示四步：连接来源、发布模型、连接应用、验证调用；
- 当前步骤有一句结果目标，不显示内部对象名；
- 浏览器返回与刷新不丢失已提交结果；
- 退出后可从“今天”恢复；
- 每一步只请求系统无法可靠推导的信息。
- 每一步提供对应任务文档入口，但默认路径不依赖用户打开文档。

### 3.2 连接来源

默认字段：来源、凭据。Base URL、组织 ID、区域和 Header 放在“自定义连接”。

提交后按阶段反馈：

```text
正在验证凭据 -> 正在获取模型 -> 已找到 18 个模型
```

失败时明确三件事：哪一步失败、凭据是否保存、如何修复。未通过验证的 Secret 不回显。

### 3.3 发布模型

默认显示最多三个推荐项，每项包含模型名、能力、来源健康和已知价格状态。用户可搜索全部模型，但不默认全选。

主动作：“发布并继续”。高级入口允许修改公开名称和能力声明；Route 与容量不在首次流程出现。

### 3.4 连接应用

输入应用名称，选择已发布模型。系统自动创建最小权限访问方式。

凭据完整值只显示一次：

- 提供复制按钮与下载受控环境变量文件的可选动作；
- 示例代码从当前 Gateway Base URL、模型和凭据变量生成；
- 不把明文凭据写进 URL、日志、DOM 持久状态或分析事件；
- 用户离开后只能轮换，不能再次查看完整值。

### 3.5 验证首次调用

页面监听真实调用，也提供“发送测试请求”。测试请求和业务请求都必须经过真实身份、Policy、Route、Usage 和 Trace 链路。

成功页只说明：应用、模型、受保护内容和下一步。技术 ID 收进“查看活动详情”。

## 4. 应用列表与详情

### 4.1 列表

默认列：名称、用途/所有者、允许模型、最近使用、费用摘要、状态。可搜索、按状态和所有者筛选。

状态只反映可行动结果：

- 正常；
- 尚未连接；
- 需要轮换；
- 受预算限制；
- 调用受影响；
- 已停用。

### 4.2 详情

页头回答：“这个应用现在能否正常使用 AI？”

页签顺序：

1. **概览**：允许模型、最近调用、费用、待处理事项；
2. **访问**：当前 Credential、轮换进度、最后使用时间；
3. **权限与预算**：模型范围、速率、并发、预算和数据策略；
4. **活动**：调用、Job、Artifact 与配置变化；
5. **集成**：代码示例、Endpoint、Webhook/Usage Sink（条件显示）。

Policy、Principal 和 Key ID 在高级详情显示，不成为页签。

### 4.3 凭据轮换

轮换是一个有状态流程：

```text
创建新凭据 -> 应用开始使用新凭据 -> 确认旧凭据无流量 -> 撤销旧凭据
```

系统显示两组凭据的最后使用时间。默认不自动撤销仍有流量的旧凭据；用户可以设定宽限期，强制撤销需二次确认。

## 5. 模型列表与详情

### 5.1 列表

默认显示已发布模型。每行包含公开名称、能力、使用它的应用数、供应状态、今日调用和费用。模型来源是同页次级视图。

### 5.2 模型详情

页头结论示例：

> `gpt-4.1-mini` 运行正常。主要来源健康，备用来源可接管。

页签：

1. **概览**：应用影响、调用、延迟和费用；
2. **供应**：自然语言供应链、容量和切换状态；
3. **访问**：哪些应用可以使用；
4. **活动**：失败、切换和配置变化；
5. **高级**：Route、Routing Group、Account Mapping 和能力声明。

### 5.3 添加备用来源

用户选择已连接来源或新建来源，系统自动验证模型兼容性。启用前展示模拟结果：受影响应用、选择顺序、价格差异、能力差异和无法回退的场景。

## 6. 用量

### 6.1 默认视图

默认时间范围为当前账期或最近 7 天，并清楚显示时区与币种。页面按以下顺序组织：

1. 总调用、成功率、成本与预算状态；
2. 按应用；
3. 按模型；
4. 异常变化；
5. 明细与导出。

图表的每个点都能下钻到同口径明细。无价格数据时显示“成本未知的调用占比”，不能把未知当成零。

### 6.2 条件能力

- 团队网关：预算、成本分摊和部门视图；
- 外部系统模式：Usage Sink 交付状态和重放；
- 内置客户模式：客户收入、成本、余额、套餐和定价；
- FinOps 权限：Effective Pricing 与 Provider Account 维度。

条件能力使用页签或高级设置，不扩张主导航。

## 7. Attention Item

### 7.1 信息结构

每个事项必须包含：

| 字段 | 说明 |
| --- | --- |
| 标题 | 用户能理解的事实，不直接使用错误码 |
| 严重度 | 依据用户影响，不依据日志级别 |
| 影响 | 应用、模型、客户、费用或数据范围 |
| 时间 | 已发生、预计发生或必须处理的截止时间 |
| 系统动作 | 已重试、切换、隔离或暂停了什么 |
| 建议动作 | 一个首选动作及预期结果 |
| 证据 | 健康、Trace、Job、审计或安全公告来源 |
| 状态 | 待处理、处理中、已解决、已忽略、已延后 |

### 7.2 动作规则

- 能安全自动修复的事项直接修复，只记录最近变化；
- 需要用户判断时才创建待处理事项；
- “忽略”必须要求原因和有效期，不允许永久吞掉严重安全事项；
- 动作执行后自动验证结果，失败时保留原事项并说明新原因；
- 相同根因按影响聚合，不让一个 Provider 故障生成几百条通知。

## 8. 页面状态规范

### 8.1 加载

- 首次加载使用稳定骨架，尺寸接近最终内容；
- 局部刷新不清空整个页面；
- 超过合理时间显示正在等待的系统，而不是无限旋转；
- 长任务允许离开，并在“今天”或活动中返回结果。

### 8.2 空状态

空状态解释为什么为空，并只给一个下一步：

- 没有应用：“连接第一个应用”；
- 没有已发布模型：“发布一个模型”；
- 没有用量：“首个调用后，用量会出现在这里”；
- 没有待处理事项：“现在没有需要处理的事项”。

不使用虚构图表或演示数据填充空页面。

### 8.3 失败

错误状态必须区分：当前操作失败、页面数据部分失败、权限不足、网络不可达和服务降级。已加载的可信数据继续显示，并标明新鲜度。

### 8.4 权限

无修改权限时保留可读上下文，隐藏或禁用动作并说明需要的角色。权限在操作期间变化时，服务端拒绝并提示刷新权限，不乐观地显示成功。

### 8.5 危险动作

停用模型、撤销仍在使用的凭据、断开来源、卸载工具和清除数据时，确认框必须展示真实影响对象。仅靠输入名称制造阻力不能替代影响说明。

## 9. 文案标准

| 避免 | 使用 |
| --- | --- |
| 创建 Gateway Principal | 连接应用 |
| 新建 Model Route | 添加模型来源 |
| Circuit Open | 主要来源已暂停使用 |
| Plugin Sidecar 不健康 | 视频工作台暂时不能提交任务 |
| Operation failed | 这次调用未完成 |
| 403 Forbidden | 你的角色无权执行此操作 |

高级详情保留原始术语和错误码，保证工程排障精度。

## 10. AI 辅助交互规格

AI 助手是可选的解释与草拟入口，不替代页面导航、表单和诊断工具。

- 用户问题自动继承当前 Application、Model、Tenant、时间和权限上下文，并明确展示；
- 每个事实结论链接到 Trace、Usage、Audit、Health 或配置证据；
- 数据冲突、样本不足或超出权限时直接说明，不生成确定性结论；
- 策略、Route 和修复建议先展示结构化差异，用户确认后由正式 API 执行；
- Credential 撤销、权限扩大、客户账务和数据外发不得自动执行；
- AI 生成内容不直接写入 Audit 事实，实际命令结果由 Core 记录；
- AI 服务不可用时页面不降级为不可操作状态。

## 11. 界面验收

- 标准首次场景不打开文档或帮助也能完成首次调用；用户需要专业信息时能在当前上下文找到准确文档。
- 正常首页不诱导无意义巡检。
- 数据陈旧或监控不完整时不显示虚假的正常结论。
- 所有失败状态说明是否已经产生或修改数据。
- 所有长任务可恢复、可追踪、可重试。
- 桌面 1280 px 与移动 390 px 下没有重叠、截断或关键动作丢失。
- 仅使用键盘和读屏器可以完成核心闭环。
- 不启用 AI 助手时，核心与专业任务仍有完整确定性路径。
